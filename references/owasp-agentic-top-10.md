# OWASP Agentic Top 10 coverage

This file uses risk identifiers and titles from OWASP Top 10 for Agentic Applications 2026, by OWASP Foundation and the OWASP GenAI Security Project. This project added application control outcomes and adversarial verification examples on September 30, 2026. Baseline: **OWASP Top 10 for Agentic Applications 2026**, published December 9, 2025. Identifiers and titles below follow the [official publication](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/). Source snapshot checked September 30, 2026. This is the Agentic Applications list, distinct from the LLM Applications and Agentic Skills lists.

The control designs and test cases below are this skill's engineering recommendations. They are a starting point for the application's threat model, not certification criteria or a promise of complete coverage. Assess combinations across categories and application-specific abuse cases.

| Risk | Required outcome where applicable | Suggested adversarial evidence |
| --- | --- | --- |
| **ASI01: Agent Goal Hijack** | Authorized task scope survives hostile content. Execution policy remains outside model-controlled instructions. | Place task-redirection fixtures in retrieval, tool output, and summaries. Force the resulting forbidden proposal through dispatch. Observe a denial with no unauthorized read or effect. |
| **ASI02: Tool Misuse & Exploitation** | A permitted tool can operate only on authorized objects, arguments, and destinations. Chains of allowed tools cannot bypass disclosure policy. | Attempt an allowed read followed by transmission to a disallowed recipient. Observe that the destination receives no data. Verify a permitted recipient still works. |
| **ASI03: Identity & Privilege Abuse** | Current authenticated authority and tenant ownership constrain every action and delegation. | Substitute another tenant's object, forge a role, revoke the caller, and queue work for later execution. Observe denial before protected access; the child never gains broader permissions. |
| **ASI04: Agentic Supply Chain Vulnerabilities** | Changes to tools, models, dependencies, skills, or schemas follow the configured provenance and review policy before use. | Substitute an unreviewed tool definition or dependency version. Observe rejection or confinement pending review, without silently falling back to the changed component. |
| **ASI05: Unexpected Code Execution (RCE)** | Model text cannot become arbitrary host execution. Necessary code execution stays within an enforced boundary. | Use inert command/path injection fixtures and controlled file/network probes. Observe text treated as data and forbidden host access blocked by the real isolation mechanism. |
| **ASI06: Memory & Context Poisoning** | Persisted or retrieved content retains its provenance and permissions and cannot become authoritative policy. | Insert hostile memory, compact it, change tenants, then revoke its source. Observe no authority increase, no tenant leakage, and no revoked material in retrieval or caches. |
| **ASI07: Insecure Inter-Agent Communication** | Authenticated, integrity-protected messages carry constrained task authority; receivers validate it independently. Protected data has confidential transport. | Forge a sender, alter the task scope, replay an old envelope, and repeat delivery. Observe rejection of unauthorized messages and no duplicate effect; verify transport configuration for protected data. |
| **ASI08: Cascading Failures** | Failures, delegation, and retries remain within cumulative budgets and defined recovery behavior. | Cause dependency failures while children spawn and retry. Observe bounded total cost/work, no duplicated effects, and containment within the intended task. |
| **ASI09: Human-Agent Trust Exploitation** | People see the actual proposed action, and approval authorizes only that action under current policy. | Supply a benign explanation with a different underlying target; mutate, expire, or replay approval. Observe the canonical preview and rejection of every mismatched or invalid authorization. |
| **ASI10: Rogue Agents** | Independent controls stop an agent that violates its mandate, including after it has started running. | Request tool expansion, audit suppression, or continued work after revocation. Observe denied escalation, retained audit evidence, and prevention of new effects by the agent and its descendants. |

For each applicable row, identify the code/configuration that enforces the outcome and the test that exercised it. Add authorized success cases. Mark absent features not applicable with a verifiable reason. An external service or library handling a feature does not automatically make the risk inapplicable.

Implement boundary details from [runtime-controls.md](runtime-controls.md) and record evidence using [verification.md](verification.md). Cross-framework alignment is described in [frameworks.md](frameworks.md).
